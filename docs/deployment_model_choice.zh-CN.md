# RTX 2060 Super 的模型选择

2026-11-14新增数据批次已完成，见[Baidu增量n/s最终报告](experiments/native_merged_v2_baiduout_20261113_results.zh-CN.md)。原图TRT FP16 batch2下，新n相比旧n测试TP由832增至835、FP由45增至60，F1由95.85%降至95.21%；新s相比旧s TP839→840、FP40→49，F1 96.55%→96.11%，定位P95由2.601降至2.504px。新增数据带来召回/误检/定位尾部取舍，暂保留旧n速度优先候选及旧/新s对照，不自动替换。当前仍没有目标卡端到端或INT8实测。以下2026-11-10及更早内容为旧批次证据与规划。

部署 GPU 由用户确认为 RTX 2060 Super。该型号常见配置为 8 GB 显存、Turing 架构（SM 7.5）；实际显存、驱动与软件版本在 Ubuntu 开机后核实。训练机仍为 RTX 3090。

2026-11-10三组原图训练及转换评估均已完成，见[最终结果分析](experiments/native_resolution_suite_v1_results.zh-CN.md)与[原图实验总表](experiments/native_resolution_suite_v1.zh-CN.md)。当前优先验证合并数据YOLO26n第24轮best＋1280×1024＋TRT FP16；合并YOLO26s第30轮保留对照。原图test F1分别95.85%/96.55%，FP16 batch2测试P95误差分别2.485/2.601px，本机普通GPU批次耗时分别3.134/4.917ms。n验证F1更高、速度更快，s测试漏检更少，不能仅按模型大小判断定位。目标2060 Super尚未实测。

下文保留此前模型规划和旧960基线背景；“尚未训练s”等是当时状态。推理优先全视野1280×1024，不因吞吐目标默认裁剪或降分辨率。

用户已确认目标为 **120 对双目画面/秒，即左右目合计 240 张图/秒**。在这个吞吐要求下，优先优化已训练的 YOLO26n；YOLO26s 改为速度有余量后的精度对比项。此前“优先尝试更大模型”的建议基于尚未明确处理速率，现在由此目标修订。2060 Super 的显存通常允许小型模型推理，但显存容量不能证明能达到 240 张图/秒；实时性必须在目标机测量。

当前安装的 Ultralytics `cfg/models/26/yolo26.yaml` 注释给出以下模型规模。它们是基础配置的参考值，包含默认类别/模型分支配置，不是本项目单类别 TensorRT 引擎的实测数据：

| 模型 | 配置注释参数量 | 配置注释计算量 | 相对 n 的计算量 |
| --- | ---: | ---: | ---: |
| YOLO26n | 约 257 万 | 6.1 GFLOPs | 1.0 |
| YOLO26s | 约 1,001 万 | 22.8 GFLOPs | 3.7 |
| YOLO26m | 约 2,190 万 | 75.4 GFLOPs | 12.4 |

这些配置注释不能换算成 2060 Super 的实际 FPS；960 输入、免 NMS 导出、单类别、算子融合、FP16 和内存/数据传输都会改变开销。扩大输入边长时，卷积部分计算量大致随像素面积增加：1280 对 960 约为 1.78 倍。实际速度比需分别测量。

在 120 对/秒目标下，建议实验次序：

1. YOLO26n，固定高×宽为 768×960，FP16，分别测试 batch=1、2。对现有 1280×1024 原图按比例缩放时恰好得到 960×768；相对 960×960 方形输入可减少 20% 输入像素，同时保留同样大小的球。当前球心评估使用 rect=True；正式矩形引擎仍需逐项验证实际预处理和输出一致性。
2. 在相同 768×960 有效输入下比较 FP32 参考与 TensorRT FP16，测球心精度变化及纯引擎/完整流程耗时；优化数据复用、GPU 预处理、异步传输、预分配和同一时刻左右目 batch=2。
3. YOLO26n，固定高×宽为 1024×1280：在保持原图采集分辨率的条件下评估精度收益及速度成本，不将加大输入视为必然改善。
4. YOLO26s：在 n 的实际速度和精度评估后决定是否训练。960 长边参考计算量约为 n 的 3.7 倍，不预先承诺满足目标。

2026-11-09 用户强调定位精度优先，能不降低分辨率就不降低。因此 800/640 长边不再列为默认下一步。当前 960 长边基线本身已将 1280×1024 原图缩小；矩形输入只减少填充，不进一步缩小球。如果相同分辨率下的优化仍不能同时满足精度与 240 张图/秒，应报告实测差距，再比较量化、模型/采集方案或硬件调整。INT8 作为有精度门槛的可选实验，不能预设无损。后续若使用 ROI，需保留完整运动范围、丢失后全图重捕获，并把裁剪偏移和缩放恢复到原图坐标，再做双目几何计算。

先固定数据和分辨率对比 n/s，之后再独立考察输入尺寸、换背景和困难负样本，避免无法解释多项修改共同造成的变化。验证集用于比较与选择；既有 830 张测试集已经评估过 n，如果反复用其选择后续模型，就应补充新的保留测试录制。

评估同时记录球心精确率、召回率、误差中位数/P95、框指标、无球与反光专项误检，以及双目每对画面的处理时间。当前预测框与历史验证框的尺寸差异，不会因模型更大自动消失；需要统一标注规范。更大模型也不能代替真实无球和眼睛/手表反光样本。

双目 30 对/秒等于 60 张图/秒，60 对/秒等于 120 张图/秒，120 对/秒等于 240 张图/秒。无并行重叠时，每对画面总预算分别为 33.3、16.7、8.3 ms；还需包含采集、解码、预处理、传输、后处理和双目关联。流水线能让阶段重叠，吞吐量与单对端到端延迟须分别测量。batch=2 的吞吐与等待/同步成本同样需要实测。

本项目的具体吞吐预算为每 8.33 ms 到达一对同步画面。若单个 GPU 对左右目串行执行 batch=1，仅推理平均每张接近 4.17 ms 就已用尽 GPU 计算吞吐预算，尚无余量给同一 GPU 上的其他工作。batch=2 需每 8.33 ms 内完成一对的推理并留出余量；batch=2 不是自动加倍速度。仅组合同一时间的左右目，无需等待多个未来时刻凑大 batch。

验收同时记录纯 GPU 引擎吞吐、包含传输/预处理的流水线吞吐、端到端延迟 P50/P95/P99、队列积压、丢帧和时间戳配对。至少持续处理 120 对/秒且队列不增长，才能认为吞吐达到目标。初步工程余量目标为纯引擎约 150 对/秒（300 张图/秒）或更高，这是规划目标，不是当前实测结果。吞吐达标不自动表示端到端延迟低于 8.33 ms；后者尚未被用户指定为独立硬性上限。

先在目标机尝试 FP16。2060 Super 支持 Tensor Core，可使用 TensorRT 的相应加速路径；实际加速取决于算子与构建结果。当前 3090/Windows engine 不视为 Ubuntu/2060 Super 的通用引擎，应迁移 PT/ONNX 和构建参数，在目标机重建。部署软件选型须核对该版本对 Turing/SM 7.5 的支持。

2026-11-09已完成当前YOLO26n第28轮候选在RTX3090上的矩形/原图FP16全量精度与速度评估，详见[正式结果](conversion_evaluation_results.zh-CN.md)及[实验总览](training_and_evaluation_overview.zh-CN.md)。960档优于直接切换原图推理，FP16显著减少本机耗时；上述实验次序的前3项本机比较已有结果。2060 Super的帧率、显存峰值和该卡FP16精度仍未实测，YOLO26s也未训练。机器可读目标记录为`configs/deployment_target.json`。
